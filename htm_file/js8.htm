6-6 ドキュメントを操作する - Document オブジェクト -

出来るだけ標準的な DOM を利用するように

ウィンドウ内に表示されたドキュメントを操作するのは、document オブジェクト （Document オブジェクト）の役割です。クロスブラウザの事を考えて、汎用性で優位にある DOM（Document Object Model)で出来る事は DOM を使うべきです。（DOM はブラウザオブジェクト とは別に標準化されている API なのであるらしい。（ベンダが独自に開発するブラウザの document オブジェクトではなくて　って事か？解ったような解らないような…）。 VBA でのファイル操作で VBA のオブジェクトを使うか FileSystemObject を使うか みたいな 物ととらえておこう。

ここでは DOM では対応していない　あるいは対応しにくい機能のみ紹介していきます。

クッキーを記録／取得する

ユーザがサイトにアクセスした途端に、パソコン内のファイルを JavaScript が 書き換えてしまう、というような事は出来ない。唯一の例外として Cookie の書き換えは出来る。

JavaScript では、document.cookie プロパティを利用する事で、クッキーを読み書きする事が できます。以下、クッキーを利用した訪問回数カウンタ。

動作確認の為にサーバーにアップする必要はなく、ただリロードすればカウンタがインクリメントされて行きます。 


   <!DOCTYPE html>

   <html lang="en" xmlns="http://www.w3.org/1999/xhtml">
   <head>
      <meta charset="utf-8" />
      <title>p241</title>
      <script type="text/javascript">
         <!--
         /* 指定されたクッキーをクライアントに書きこむ為の
         setCookie 関数を定義。引数には、先頭から
         クッキー名」「値」「有効期限」「ドメイン」「パス」
         SSL を必要とするか」を設定する
         SSL（Secure Sockets Layer）通信を暗号化する技術です。
         */
         function setCookie(name, value, expires, domain, path, secure) {
             // クッキー文字列を格納するための変数 c を宣言
             var c = '';
             // 「名前 = 値」を追加（値はあらかじめエンコード処理）
             c += name + '=' + encodeURIComponent(value);
             // 引数 expires が殻で無い場合、expires 日後に有効期限を設定
             if (expires) {
                 var exp = new Date();
                 exp.setDate(exp.getDate() + expires);
                 c += '; expires=' + exp.toGMTString();
             }
             /* 引数 domain, path, secure が殻で無い場合、
             それぞれ該当するパラメータを設定*/
             if (domain) { c += '; domain=' + domain; }
             if (path) { c += '; path=' + path; }
             if (secure) { c += '; secure'; }
             // できあがったクッキー文字列をクライアントに書き込み
             document.cookie = c;
         }

         // 指定された名前のクッキー値を取得する getCookie 関数を定義
         function getCookie(name) {
             // 取得したクッキー文字列を「;」で分割
             var cs = document.cookie.split(';');
             // 個々のクッキー情報（名前=値）を順番に確認
             for (var i = 0; i < cs.length; i++) {
                 /*「=」でクッキー情報を分割し、名前部分が引数 name と
                 等しい場合 その値を出コードした上で戻り値として返す*/
                 var kv = cs[i].split('=');
                 if (kv[0] == name) {return decodeURIComponent(kv[1]); }
             }
             // 該当する無眼のクッキーがない場合は null を返す
             return null;
         }

         // 'js_cnt'という名前のクッキー値（カウンタ値）を変数 cnt にセット
         var cnt = getCookie('js_cnt');
         // 変数 cnt が殻でない場合はインクリメント、空の場合は１をセット
         cnt = cnt ? ++cnt : 1;
         // 変数 cnt の値をクッキー 'js_cnt' にセット（有効期限は90日）
         setCookie('js_cnt', cnt, 90);
         // カウント値を表示
         document.write(
         'あなたはこのサイトに ' + cnt + ' 回、アクセスしました。');
         //-->
      </script>
   </head>
      <body><h1>クッキーのテスト</h1></body>
   </html>

（１）クッキー値を設定する - setCookie 関数 -

setCookie 関数は、document.cookie プロパティに設定するクッキー文字列を生成しています。 cookie プロパティに値を設定するための書式は以下の通りです。 （太字のみ必須で、あとは任意） 


   クッキー名 = 値; expires = 有効期限; domain = ドメイン名; pth = パス; secure

必要な情報は、セミコロン区切りの「マラメータ名=値」で記述します。 それぞれのパラメータの意味は以下の通りです。

クッキー文字列のパラメータ
パラメータ概要
クッキー名 クッキーを識別する名前とその値（最低限必須）。英数字意外の文字列を含む場合は encodeURIComponent 関数で予めエンコードしておく必要があります。
expires クッキーの有効期限（グリニッジ標準時）。有効期限を過ぎたクッキーは自動的に削除 。省略時はブラウザを閉じた時に削除。過去の日時が指定された場合は即座に削除。
domain 有効なドメイン。指定ドメインのページでのみクッキーを利用可能 （省略時は現在のドメイン）
path 有効なパス。指定パス配下のページでのみクッキーを利用可能（省略時は現在 のドメイン）
secure SSL(Secure Socke Layer)通信でのみクッキーを送信するか

（２）クッキー値を取得する - getCookie 関数 -

クッキーを取得するのも、書き込む場合と同様、 document.cookie プロパティ を使います。クッキー値は以下のような形式でまとまっているので、 解析して取得するのが getCookie 関数の役割です。 


   クッキー名１= 値１; クッキー名２ = 値２;　…

onload で writeln が実行されると、writeln は新しいドキュメントをオープンする のです。

ということで、writeln メソッドはイベントハンドラから利用すべきでは ありません。イベントハンドラからコンテンツを書き換えるには 、後述する innerHTML プロパティなどを使用します。

writeln メソッドの利用は、以下２つのケースにほぼ、限られます。

  • デバッグ用途
  • サブウィンドウに対してコンテンツを出力する

サブウィンドウに対してコンテンツを出力するサンプル 


   <!DOCTYPE html>
   <html lang="en" xmlns="http://www.w3.org/1999/xhtml">
   <head>
       <meta charset="utf-8" />
       <title>p245</title>
       <script type="text/javascript">
           // [開く] ボタンをクリックしたタイミングでサブウィンドウを生成
           function winOpen() {
               var subwin = window.open('', 'Child', 'width=200,height=200');
               subwin.document.open('text/html');
               subwin.document.writeln('入力値:');            
               subwin.document.writeln(subwin.opener.document.fm.data.value);
               subwin.document.writeln('<br /><input type="button" value="閉じる"');
               subwin.document.writeln('onclick="self.close();" />');
               subwin.document.close();
           }
       </script>
   </head>
   <body>
       <form name="fm">
           <input type="text" name="data" value="出力される文字列" />
           <input type ="button" value="開く" onclick="winOpen()" />
       </form>
   </body>
   </html>

window.open メソッドで開いたドキュメントに対して、 コンテンツを書き込むには、以下のように記述します。 


   ウィンドウ名.document.open('text/html');
   ウィンドウ名.document.writeln('…');
   ウィンドウ名.document.close();

コンテンツ出力の開始を表す open メソッドは省略可能ですが、 close メソッドは省略できません。ブラウザのロード中アニメーションが 動いたままになってしまいます。（そうなる場合があるらしい・・・）

サブウィンドウを閉じるには self.close(); で閉じます。 self は現在のウィンドウを表す Window オブジェクトです。

Chapter7　HTML や XML の文書を操作する～ DOM (Document Object Model)

7-1 DOM(Document Object Model)の基本

クロスブラウザを意識するために

「ブラウザオブジェクトはあくまでここのブラウザが独自に実装したオブジェクトで、 これといった標準の規格が存在するわけではない。」

そこで登場したのが DOM(Document Object Model)です。 DOM は HTML や XML のようなマークアップ言語で書かれたドキュメントにアクセスするための 「標準的な」しくみで、クロスブラウザ環境でも互換性の高いコードを記述できます。

DOM のしくみ

DOM では、Document Object Model という名前の通り、 文shに含まれる要素や座億世、テキストをそれぞれオブジェクトと見なし、 「オブジェクトの集合（階層関係）が文書である」と考える。

ちなみに、文書を旺盛する要素や属性、テキストといったオブジェクトのことをノード と呼び、オブジェクトの種類に応じて要素ノード、属性ノード、テキストノード などと 呼びます。DOMは、これらノードを抽出／追加／置換／削除するための汎用的な 手段を提供する API(Application Programming Interface:関数やオブジェクトの集合) と言えます。

文書ツリーの解釈はブラウザごとに違う

じつは、文書ツリーの解釈はブラウザ（やバージョン）によって微妙に異なります。

  • ノード間の空白／改行（空白ノード）を無視する
  • <title>要素配下のテキストノードを無視する

特に空白ノードの認識の認識の要注意です。今後、ノードを抽出する際に 「○○番目の子ノード」と指定することがありますが、文書ツリーの会社の違いによって、 同じコードでは同じノードを抽出できない可能性があるのです。

こうした違いを九州する方法については後述しますが、ここではまず、 「空白ノードには要注意」とだけ憶えておきましょう。

DOM の３つのレベル

DOMは、Web技術の標準化団体である W3C(World Wide Web Consortium) で標準化が 進められ、現在は Level1, 2, 3と３つのレベルがあります。レベルの大きい物がより 高度な機能を提供すると思っておけば良いでしょう。

レベル勧告時期概要
Level1 1998/01 ノードの参照／追加／置換／削除などの基本機能を定義
Level2 2000/11 Level1に、スタイル操作やイベントモデル、ノードの範囲指定などの機能を追加
Level3 2004/04(一部) Level2に、XPath、妥当性の検証、読み込み／保存などの機能を追加

現時点での最新レベルは Level3 ですが、執筆時点で正式に勧告となっているものは 一部のモジュールに留まっており、XPathやイベントモデルなどのモジュールは策定段階 にあります。ブラウザ側の実装も、基本は Level2 がベースになっています。

また、時として「DOM Level 0」「DOM 0」という言葉が登場することもありますが、 これはDOM Level1 が作成される前の -- 標準化されていないブラウザオブジェクトの事です。 標準仕様としての「DOM Level 0」が存在するわけではありません。

7-2 特定のノードを取得する

ノードを取得する２つの方法

DOM のノードにアクセスする方法は大きく２つに分類できます。

  • ID値やタブ名といったキーによって目的の要素を直接取得するダイレクトアクセス
  • ある要素を起点にその子要素、親要素、兄弟要素を、というように 相対的な位置関係でノードを取得する ノードウォーキング

要素を取得していく方法として、ダイレクトアクセス（１～３）、 ノードウォーキング（４）の順で紹介していきます。

  1. ID値で検索する方法
  2. タグ名で検索する方法
  3. class属性（スタイルクラス）で検索する方法
  4. 相対的な位置関係で取得る方法

ダイレクトアクセスとノードウォーキングには、それぞれ以下のメリットとデメリット があります。

  • ダイレクトアクセス　⇒　ピンポイントで特定の要素を取得するには便利だが 大きな文書（または部分ツリー）を対象とする場合にはパフォーマンス低下の原因とも なりやすい
  • 操作の小回りが利くが、ダイレクトアクセスに比べると手続きがやや回りくどい

そのため、「ダイレクトアクセスで部分的なツリーを取得した後、 近接するノードはノードウォーキングで取得する」など、状況に応じて両者を併用する のが好ましい。

NodeList オブジェクトは配列のように扱えるように作られていますが、 Arrayオブジェクトではありません。for 文で要素を取得は出来ますが、 for in 構文で要素にアクセスすると、ブラウザによって異なりますが、少なくとも length 以上の要素を吐きだします。何が出力されるのか判って使わないとバグの元になります。

　NodeListに3つの要素が格納されているとしましょう。最初の要素を取り出すためには、本来、itemメソッドを使います。


   var nodeList = document.getElementsByTagName('div');
   var elmObject = nodeList.item(0);

itemはメソッドですので、( )を使ってインデックス番号を 指定します。item[0]ではありませんので注意してください。

インデックス番号は配列と同じく0から数えます。 この例は、次の記法と同等です


var elmObject = nodeList[0];
