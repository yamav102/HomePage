その振舞いオブジェクト如し -クロージャ-

クロージャとは「ローカル変数を参照している関数内関数」の事。 


   function closure(init) {
       var counter = init;
       
       return function () {
          return ++counter;
       }
   }
   var myClosure = closure(1);
   document.writeln(myClosure() + '<br>'); 
   // 2

   document.writeln(myClosure() + '<br>'); 
   // 3

   document.writeln(myClosure() + '<br>'); 
   // 4

   document.writeln(myClosure() + '<br>'); 
   // 5

引数が戻り値が関数である関数の事を「高階関数」と言うのでした。 Closure は高階関数です。 通常、関数内で使われたローカル変数（ここでは変数 counter）は、関数の処理が終了した 時点で破棄される筈です。しかし、closure 関数から返された匿名関数 myClosure が ローカル変数 counter を参照し続けている ので、closure 関数の終了後も、 ローカル変数 counter は保持され続けます。

まずは、最初の　closure 関数よびだしで、変数 mClosure に匿名関数がセットされます。 ここで匿名関数 myClosure は、ローカル変数 counter を維持しつつも、（closure 関数自体は 終了していますので）もともとの Closure 関数とは独立して動作できるようになります。

ここまでの説明なんかまどろっこしい。 「オブジェクトの如し」などと言わずに、closure をクラスと見立てれば 別に普通のオブジェクトの動作と言える。 


   function closure(init) {
       var counter = init;
       
       return function () {
          return ++counter;
       }
   }
   var myClosure = closure(1);
   var myClosure2 = closure(1);

   document.writeln(myClosure() + '<br>'); 
   // 2

   document.writeln(myClosure2() + '<br>'); 
   // 2

   document.writeln(myClosure() + '<br>'); 
   // 3

   document.writeln(myClosure2() + '<br>'); 
   // 3

   document.writeln(myClosure() + '<br>'); 
   // 4

   document.writeln(myClosure2() + '<br>'); 
   // 4

   document.writeln(myClosure() + '<br>'); 
   // 5

   document.writeln(myClosure2() + '<br>'); 
   // 5

closure 関数が呼び出されたタイミングで、

  • 匿名関数を表す Call オブジェクト
  • closure 関数の Call オブジェクト
  • グローバルオブジェクト

というスコープチェーンが形成されます。Call オブジェクトは関数呼び出しの都度に 生成されるので、それぞれのスコープチェーンは独立したもの　－　そして、その中で 管理されるローカル変数 counter もまた「別物」なのです。

クロージャは「シンプルなオブジェクト」

クロージャとオブジェクトの比較
クロージャ オブジェクト
クロージャを括っている親関数 コンストラクタ
クロージャから参照されるローカル変数 プロパティ
クロージャ自身 メソッド
関数の呼び出し インスタンス化
クロージャをを格納する変数 インスタンス

クロージャとオブジェクトは等価ではありません。 まず、クロージャは、その構造上、ひとつのスクープに対して、持てる処理はひとつだけです。 上記のサンプルコードであれば、counter をインクリメントする事は出来ても、 同じローカル変数 counter をデクリメントする仕組みを追加する事が出来ません。 （厳密には、クロージャの動作を引数で切り替えるようにすれば可能ですが、それは本質的な 解決ではありません）。

  • 変数（群）に伴う処理を一つしか必要としない ⇒　クロージャ
  • 複数の処理を必要とするケース　⇒　オブジェクト

という使い分けが出来ます。クロージャは処理をひとつしか持たないオブジェクトなのです。

Chapter5-1 JavaScriptにおけるオブジェクト指向の特徴

「クラス」はなく「プロトタイプ」

JavaScriptは歴（れっき）としたオブジェクト指向言語です。しかし、いわゆるクラスがなく、 「プロトタイプ」という概念だけが存在します。このため JavaScript のオブジェクト指向は プロトタイプベースのオブジェクト指向 と呼ばれる事があります。

もっともシンプルなクラスを定義する

次が中身を持たない（もっともシンプルな）「クラス」です。 


   var Member = function(){};

ただの中身のない関数リテラルを変数に代入したもの。これが JavaScript のクラスなのです。 実際、この Memberクラスは、new演算子でインスタンス化できます。 


   var Member = function () { };
   var mem = new Member();
   document.writeln(mem.toString());
   // [object Object]

JavaScript では関数（Function オブジェクト）にクラスとしての役割を与えています。

コンストラクタで初期化する

new 演算子によってオブジェクトを生成する事を想定した関数オブジェクトのことを コンストラクタ と言います。上のサンプルでは Member関数がクラスそのものであり コンストラクタです。

コンストラクタの名前は、普通の（コンストラクタではない）関数と区別するために、 大文字で始めるのが一般的です。

プロパティとメソッド

作成したコンストラクタに初期化処理を記述してみます。 


   var Member = function (firstName, lastName) {
       this.firstName = firstName;
       this.lastName = lastName;
       this.getName = function () {
          return this.lastName + ' ' + this.firstName;
       };
   };
   var mem = new Member('祥寛', '山田');
   document.writeln(mem.getName()); 
   // 山田 祥寛

this キーワードは、コンストラクタによって生成されるインスタンス（つまり、自分自身） を表すものです。this キーワードに対して変数を指定する事で、インスタンスのプロパティを 設定できます。

また、プロパティには文字列や整数、日付けなどだけではなく、関数オブジェクト（関数リテラル）を 指定できる点にも注目して下さい。JavaScript においては、厳密にはメソッドという独立した 概念はなく、 値が関数オブジェクトであるプロパティがメソッドと看做される のです。 ここでは、 getname プロパティに匿名関数を引き渡していますので、いわゆる「getName メソッド」 を宣言した事になる訳です。

コンストラクタ関数は戻り値を返してはいけません。

動的にメソッドを追加する

生成したオブジェクトに、後からメソッドを追加する事も出来ます。 


   var Member = function (firstName, lastName) {
       this.firstName = firstName;
       this.lastName = lastName;
   };
   var mem = new Member('祥寛', '山田');

   mem.getName = function () {
       return this.lastName + ' ' + this.firstName;
   }

   document.writeln(mem.getName()); 
   // 山田 祥寛

新たにインスタンスを生成して getName メソッドを呼び出すとどうなるのか？ 


   var Member = function (firstName, lastName) {
       this.firstName = firstName;
       this.lastName = lastName;
   };
   var mem = new Member('祥寛', '山田');

   mem.getName = function () {
       return this.lastName + ' ' + this.firstName;
   }

   document.writeln(mem.getName()+'<br>'); 
   // 山田 祥寛 

   var mem2 = new Member('たろう', 'ほげほげ');
   
   /*
   実行されない。ブラウザによっては
   「サポートされていません」っぽいエラーメッセージが出る？
   */
   document.writeln(mem2.getName());

mem2 オブジェクトは getName メソッドは実装されていません。 要するに、クラスにではなくインスタンスに対してプロパティやメソッドが追加される という事です。JavaScript の世界では、 同一のクラスをもとに生成されたインスタンスであっても、それぞれが持つメンバは同一であるとは限らない という事です。

サンプルでは新たにメンバを追加しているだけですが、 delete 演算子 でインスタンスから既存の メンバを削除する事もできます。 


   delete mem.getName;

プロトタイプは「より縛りの弱いクラスのようなもの」。

Chapter5-2 コンストラクタの問題点とプロトタイプ

クラスのインスタンスに実装されるメソッドというのは、 インスタンスを沢山生成する分コピーされてしまい、実行される処理は同じなのだから 一つ用意されていれば済むメソッドの為に、多くのメモリが無駄に消費されてしまいます。

多くの言語で、この辺の事はメモリが無駄に消費されないように、コピーされるのは メンバ変数の分のメモリ領域だけ、という仕様になっているものですが、 JavaScript では自ら「全てのインスタンスから参照される処理」として明示する必要があります。 その仕組みを実現するのが prototypeプロパティです。

prototype プロパティはObjectオブジェクトのプロパティのようです。 MSDNには次のように解説されています。

組み込み JavaScript オブジェクトはすべて、値の取得のみ可能な prototype プロパティを持っています。 プロパティとメソッドはプロトタイプに追加できますが、オブジェクトを別のプロトタイプに割り当てることはできません。 ただし、ユーザー定義オブジェクトは、新しいプロトタイプに割り当てることができます。 この言語リファレンスには、組み込みオブジェクトごとにメソッドとプロパティの一覧があり、オブジェクトのプロトタイプに含まれているメソッドとプロパティを調べることができます。

Member オブジェクトに含まれる getName メソッドをプロトタイプとして定義します。 


   var Member = function (firstName, lastName) {
       this.firstName = firstName;
       this.lastName = lastName;
   };
   var mem = new Member('祥寛', '山田');

   Member.prototype.getName = function () {
       return this.lastName + ' ' + this.firstName;
   }

   document.writeln(mem.getName()+'<br>'); 
   // 山田 祥寛 

   var mem2 = new Member('たろう', 'ほげほげ');
   
   document.writeln(mem2.getName()); 
   // ほげほげ たろう

JavaScript のクラスってこんなんです。クラスという抽象的な設計図が存在しない。 JavaScript のクラスにあるのは、あくまで実体化されたオブジェクトだけ。 新しいオブジェクトを生成するにも（クラスではなく）オブジェクトが元になっているのです。 そして、新しいオブジェクトを作る為の原型（雛型）を表すのが、それぞれのオブジェクトに属する 「プロトタイプ」という特別なオブジェクトであるわけです。

上記のサンプルコードは、Memberオブジェクトを生成してから getName を定義しています。 getName を定義してから、Memberオブジェクトを生成してもどちらでも正しいコードです。 プロトタイプへの変更は随時行う事ができ、リアルタイムに反映されます。

プロトタイプオブジェクトでプロパティを設定した場合の挙動

インスタンス単位で個別に保有するプロパティをプロトタイプオブジェクトで宣言する 意味はありません（読みとり専用のプロパティは別です）。通常は以下のように使い分けます。

  • プロパティの宣言　⇒　コンストラクタで
  • メソッドの宣言　⇒　プロトタイプで

あえてプロパティをプロトタイプオブジェクトで宣言すると、次のような挙動になります。 


   var Member = function () {};
   Member.prototype.sex = '男';

   var mem1 = new Member();
   var mem2 = new Member();
   
   document.writeln(mem1.sex + '|' + mem2.sex + '<br>'); 
   // 男|男 --①

   mem2.sex = '女';   
   document.writeln(mem1.sex + '|' + mem2.sex + '<br>'); 
   // 男|女 --②

①ではsexプロパティをmem1・2とも持っていないので、プロトタイプオブジェクトの持つ sex プロパティを「暗黙的に参照」します。ところが、②では、mem2のプロパティ が置き換えら「インスタンスmem2自身が sex プロパティを持っている」ので、インスタンスmem2は プロトタイプを参照する必要が無くなります。 結果、インスタンスmem2に設定されている sex プロパティが参照されます。 これを、「インスタンスの sex プロパティがプロトタイプの sex プロパティを 隠蔽 する」と言います。

静的プロパティ／静的メソッドを定義する

静的プロパティ／静的メソッドとは、インスタンスを生成ｓｈなくてもオブジェクトから 直接呼び出せるプロパティ／メソッドのことです。インスタンス経由で呼び出すのが、 インスタンスプロパティ／インスタンスメソッドと呼ぶのでした。

静的プロパティ／メソッドはプロトタイプオブジェクトには登録できません。プロトタイプオブジェクトは あくまで「インスタンス」から暗黙的に参照される事を目的としたオブジェクトです。 静的プロパティ／静的メソッドは、以下のようにコンストラクタ（オブジェクト）に 直接追加します。 


   var Area = function () {};
   // コンストラクタ

   Area.version = '1.0'; 
   // 静的プロパティの定義

   // 静的メソッド triangle の定義
   Area.triangle = function (base, height) {
       return base * height / 2;
   }

   // 静的メソッド diamond の定義
   Area.diamond = function (width, height) {
       return width * height / 2;
   }

   document.writeln('Areaクラスのバージョン :' + Area.version + '<br>'); 
   // 1.0

   document.writeln('三角形の面積 :' + Area.triangle(5, 3) + '<br>'); 
   // 7.5   

   document.writeln('菱形の面積 :' + Area.diamond(10, 2) + '<br>'); 
   // 10
   
   var a = new Area();
   document.writeln('菱形の面積 :' + a.diamond(10, 2) + '<br>'); 
   // 実行されない（ エラー）
静的プロパティ／静的メソッドを定義する時の２つの注意点

（１）制定プロパティは、インスタンスプロパティとは異なり、「クラス単位で保有される情報」です。 つまり、その内容を変更した場合、スクリプト内の全てに変更が反映されてしまう事になります。 原則として、静的プロパティで定義する値は、読みとり専用の用途に限定すべきです （静的プロパティを編集する静的メソッドは作るな、という事）。

（２）静的メソッドの中では、this キーワードは使えない、というか使っても意味がない。 インスタンスメソッドの中での this キーワードは、インスタンス自身を表します。 一方、静的メソッドの中での this キーワードはコンストラクタ（関数オブジェクト）を表します。 インスタンスが内のですから当然ですが、静的メソッドからインスタンスプロパティの値にアクセスする事 は出来ません。正確には、「静的メソッドの中では、thisキーワードを使っても意味がない」がより 正しいのですが、インスタンスメソッドと同様の意味での「thisキーワードは使えない」と覚えておくのが シンプルです。

なぜ静的メンバを定義するのか

静的メンバは、機能的にはグローバル変数／関数と何ら変わりありません。 「それならば、別に静的プロパティ／静的メソッドなど使わず、素直にグローバル変数／関数を 使えばよいのではないか」とおもわれるかもしれませんね。

しかし、これは不可です。 というのも、グローバル変数／関数は、名前が競合する原因となるからです。

たとえば１００個のグローバル変数／関数を含んだライブラリを考えてみましょう。 アプリケーションからこのライブラリを使おうとした場合、ここで定義された １００個の名前はいわゆる予約後になりますから、アプリケーションでは利用する事が出来ません。 もし間違って上書きしてしまった場合に、は、元の機能や情報は失われてしまいます。 グローバル変数／関数は多くなればなるほど、アプリケーション側では 名前の場っていんぐを意識してコードを書かなければならなくなってしまうのです。

これは当然このましい状態ではありませんので、グローバル変数／缶すうはできるだけ少なくなるように するべきです。静的メンバを利用すれば、変数／関数はクラスの配下に属する事になりますので、こうした 競合の可能性を減らすことが出来ます。

グローバル変数／関数はできるだけ減らすこと、そのためには関連する既往や情報は静的メンバに まとめること－－－－－－－心かげましょう。

プロトタイプオブジェクトでプロパティを削除した場合の挙動

プロトタイプオブジェクトでプロパティを削除する場合にも、インスタンス単位で行われます。 


   var Member = function() {};
   // コンストラクタ
   
   Member.prototype.sex = '男';
   
   var mem1 = new Member();
   var mem2 = new Member();
   
   document.writeln(mem1.sex + '|' + mem2.sex + '<br>'); 
   // 男|男
   
   mem2.sex = '女';
   document.writeln(mem1.sex + '|' + mem2.sex + '<br>');  
   // 男|女
   
   delete mem1.sex;
   // ----①

   delete mem2.sex;
   // ----②
   
   document.writeln(mem1.sex + '|' + mem2.sex + '<br>'); 
   // 男|男----③

①でdelete演算子は「インスタンスmem1の」sex プロパティを削除しようとしますが、 インスタンスmem1 は sex プロパティを持ちませんので、delete演算子はなにも行いません （プロトタイプまで遡って削除することはありません）。結果③でインスタンスmem1 は、 暗黙の参照をたどってプロトタイプオブジェクトの sex プロパティを返します。 つまり、結果は「男」になります。

一方、②では、インスタンス mem2 が自分自身で sex プロパティを持ちますので、delete演算子は これを削除します。結果、③でインスタンス mem2 も暗黙参照をたどって、プロトタイプオブジェクト の sex プロパティ「男」を返すことになります。

繰り返しになりますが、 インスタンス側でのメンバの追加や削除といった操作が、プロトタイプオブジェクトにまで影響を及ぼすことは ありません。

インスタンス単位でプロトタイプのメンバを削除する

次のように記述することで、プロトタイプオブジェクトのメンバを削除する事ができます。 


   delete Member.prototype.sex;
   document.writeln(mem1.sex + '|' + mem2.sex); 
   // undefined|undefined

この書き方は、プロトタイプを参照しているすべてのインスタンスに影響を及ぼします。 プロトタイプで定義されたメンバを「インスタンス単位で」削除したい場合、 ややトリッキーですが、定数 undefined を用いる方法があります。 


   var Member = function() {};
   // コンストラクタ
   
   Member.prototype.sex = '男';
   
   var mem1 = new Member();
   var mem2 = new Member();
   
   document.writeln(mem1.sex + '|' + mem2.sex + '<br>'); 
   // 男|男   

   mem2.sex = undefined;
   document.writeln(mem1.sex + '|' + mem2.sex); 
   // 男|undefined

ここでは、sexプロパティの値を定数 undefined で上書きする事で、「擬似的」に メンバを無効化しています。値を強制的に未定義にしているだけで、 メンバを削除しているワケではないので、 for in ループでオブジェクト内のメンバを 列挙した場合には、sexプロパティは依然として存在するものとして表示される事になります。 


   function Member() {};
   
   var mem = new Member();
   
   Member.prototype.sex = '男';
   Member.prototype.hoge = undefined;
   
   
   for(var prp in mem){            
       document.writeln(prp + ' : ' + mem[prp] + '<br />');
   }
   /*
   sex : 男
   hoge : undefined
   */

オブジェクトリテラルでプロトタイプを定義する

些細な事ですが、毎回「Member.prototype.～」という記述を繰り返さなければ ならないのは面倒ですし、オブジェクト名が変更になった場合、 全ての定義箇所を書き換えなければならないのは嬉しくありません。 また、個々のメンバ定義が独立したブロックで記述されている事から、 「どこからどこまでが同じオブジェクトのメンバ定義であるのか、一見して 見えにくい」という可読性の問題もあります。

そこで登場するのが、オブジェクトリテラル表現です。 


   /*
   ドット演算子を使った場合
   Memberオブジェクト名に変更がはいったら全部直さなくてはならない。
   独立した個々の文から成るため、どこまでが一つのプロトタイプの
   定義なのか判別しにくい
   */
   var Member = function (firstName, lastName) {
       this.firstName = firstName;
       this.lastName = lastName;
   };
   Member.prototype.getName = function () {
       return this.lastName + ' ' + this.firstName;
   };

   Member.prototype.toString = function () {
       return this.lastName + this.firstName;
   };

   var mem = new Member("hogeTaro", "Fujii");
   window.alert(mem.toString());



   /*
   リテラル表現を使った場合
   Member.prototype という記述が一つにまとめられて
   オブジェクト名の変更が容易。
   定義が一つのブロックにまとまっていて、コードが読み易い。
   */
   var Member = function (firstName, lastName) {
       this.firstName = firstName;
       this.lastName = lastName;
   };
   
   Member.prototype = {
       getName: function () { return this.lastName + ' ' + this.firstName; },
       toString: function () { return this.lastName + this.firstName }
   };

   var mem = new Member("hogeTaro", "Fujii");

Chapter5-3 オブジェクトの継承 - プロトタイプチェーン -

プロトタイプチェーンの基礎 


   var Animal = function(){};
   Animal.prototype = {
       Walk : function(){document.writeln('トコトコ…'+'<br />');}
   };

   var Dog = function(){};
   // コンストラクタ

   // Animalクラスを継承
   Dog.prototype = new Animal();

   // メソッドを差分プログラミング
   Dog.prototype.bark = function(){
       document.writeln('ワンワン!' + '<br />');
   };

   var d = new Dog();
   d.Walk(); 
   // トコトコ…
   d.bark(); 
   // ワンワン！

JavaScriptではプロトタイプオブジェクトにスーパークラス（基底クラス） を参照させる事で 継承 を実現している。Objectクラスは 全てのクラスにとってのスーパークラスなので、全てのプロトタイプオブジェクトは Objectオブジェクトを暗黙で参照している。 プロトタイプチェーンは、Objectオブジェクトのプロトタイプオブジェクトまで 、プロパティやメソッドが見つかるまで検索を遡って実行する。

だから、Object.prototype に仕込まれたプロパティ・メソッドは全ての オブジェクトで使用可能となる。（影響が大き過ぎるので、やるべきではない、とされる。）

継承関係は動的に変更可能

JavaやC++のような言語でオブジェクト指向では、継承とはあくまで静的なものである（ いったん決定した継承関係を途中で変更することはできない）のに対し、 JavaScriptによる継承は動的なもの。つまり、同一のオブジェクトが、あるタイミングでは、 オブジェクトXを継承しており、次のタイミングではオブジェクトYを継承している、 という事も可能。 

   var Animal = function(){};
   Animal.prototype = {
       Walk : function(){document.writeln('トコトコ…'+'<br />');}
   };

   var SuperAnimal = function () { };
   SuperAnimal.prototype = {
       walk: function () { document.writeln('ダダダダダ！' + '<br />'); }
   };

   var Dog = function () { };

   // DogクラスにAnimalオブジェクトを継承
   Dog.prototype = new Animal();
   var d1 = new Dog();

   d1.Walk(); 
   // トコトコ…

   // DogクラスにSuperAnimalオブジェクトを継承
   Dog.prototype = new SuperAnimal();
   var d2 = new Dog();

   d2.walk(); 
   // ダダダダダ！

   d1.Walk(); 
   // ？？？？？ ---------①

Dogオブジェクトのプロトタイプは Animal オブジェクトです。しかし、 ①の時点では、既に SuperAnimal オブジェクトに差し変わっています。

参照がリアルタイムに変更を認識する事を考えれば、①では SuperAnimal オブジェクトの walk メソッドが呼び出され、「ダダダダダ！」が出力されるように思えます。 しかし、結果は「トコトコ…」Animal オブジェクトの walk メソッドが呼び出されます。

JavaScript のプロトタイプチェーンは インスタンスが生成された時点で固定され、その後の変更に関わらず保持されます。

ここで注目していただきたいのは、initializeBase関数です。 initializeBase関数は、派生クラスのコンストラクタの中で呼び出されることを想定した関数で、 以下のような役割を提供します。

  • 基底クラスのコンストラクタを呼び出す
  • 基底クラスで定義されたメンバを、派生クラスにコピーする

initializeBase関数を呼び出す構文は、以下の通りです。 


   initializeBase(現在のインスタンス, 親クラス, 引数配列)

⇒基底クラスのコンストラクタを呼び出すとともに、現在のクラスに対して 親クラスで定義されたメンバをコピーします。「引数配列」は親クラスのコンストラクタに 渡す引数です。（引数がない場合は空の配列「[]」を渡します）

以下では、これら引数の意味を念頭に置いたうえで、initializeBase関数の中身を具体的に読み 解いていくことにしましょう。

まず、基底クラスのコンストラクタを呼び出しているのがリスト 5-17① の部分です。 派生クラスは、基底クラスの初期化処理に独自の初期化処理を対kあする形で初期化するのが 一般的です。独自の処理は派生クラスのコンストラクタに任せれば良いので、 initializeBase関数では基底クラスのコンストラクタを呼び出すまでを行うのです。

base.apply(derive,baseArgs);
↓ ↓ ↓

applyメソッドは、Functionオブジェクトが提供するメソッドのひとつえ、その関数をあたかも指定 されたオブジェクト（ここでは引数derive）のメソッドであるかのように呼び出す事ができます。

ここでは引数 deriveに、派生クラスのコンストラクタから this キーワードが渡されています。 つまり、今作成しようとしている派生クラス（インスタンス）のメソッドとして、 親クラスのコンストラクタ（Member関数）を呼び出しているわけです。メソッド（コンストラクタ ）呼び出しに必要な引数は、applyメソッドの第２引数で、配列リテラルで指定します。

なお、派生クラス独自の初期化処理を追加したい場合には、②のように派生クラスのコンストラクタの中に処理を記述します。

次に基底クラスで定義されたメンバを、派生クラスでも使えるようにコピーしているのが ③の部分です。先述したように、基底クラスで利用可能なメンバ（メソッド）は、 プロトタイプオブジェクト（prototypeプロパティ）の配下につ六されているはずです。 そこでここでは、このプロトタイプオブジェクトの内容を for…in ループですべて取り出し、 そのまま派生クラスのプロトタイプオブジェクトにセットしています。ただし、 派生クラスで同盟のメソッドが既に定義されいる場合を考慮し、同名のメソッドが 存在しない場合にだけコピー処理を行うものとします。

また、ここで代入する先はインスタンスのプロトタイプオブジェクトではなく、 コンストラクタ関数（ここではSpecialMember）のプロトタイプオブジェクトである 点にも注意してください。引数deriveには派生クラスのインスタンスがセットされているはずですので、ここではconstructorプロパティでコンストラクタを取得しています。

以上で、継承の手続きは完了です。リスト5-17の④をみても、派生クラスで確かに基底クラスの メンバにアクセスできていることが確認できます。

ただし、この方法を利用した場合には一点だけ注意が必要なのは、 「継承されるメンバは、インスタンス化の際、静的に決まってしまう」という点です。 プロトタイプチェーンのときのように、基底クラスのプロトタイプオブジェクトに 対する変更をリアルタイムに認識することはありません。

補足：基底クラスのメソッドを派生クラスで利用するには

派生クラスでメソッドを定義する場合、単に新たなメソッドを追加するばかりではなく、 基底クラスで定義されたメソッドをオーバーライド（上書き）する事があります。 また、その際に一から機能を実装するのではなく、基底クラスで定義された機能を 流用しながら、差分の機能を追加したいという場合があります。

そのような時には、「派生クラスのメソッドから、基底クラスのメソッドを呼び出す」 という行為が必要になります。

具体的な例を見てみましょう。以下は、Memberクラスで定義されたgetNameメソッドを 上書きして、名前の末尾にロール情報（role）を追加してみます。

       base.apply(derive, baseArgs); //--------------①

       apply は関数オブジェクトの（プロトタイプチェーンで継承された）
       提供するメソッド。
       派生クラスのメソッドとして親クラスのメソッドを呼び出している。
       クラスを継承に引数がある場合

       /*③プロトタイプのコピー
       派生クラスのプロトタイプが持っていない
       親クラスのプロパティやメソッドや

	     //getNameメソッドの関数リテラル

   // Memberクラスを定義
   var Member = function (firstName, lastName) {

   基底クラス名.prototype[メソッド名].apply(現在のインスタンス, 引数)

⇒ 基底クラスで定義されたメソッドを呼び出します。
