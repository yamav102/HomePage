プライベ―トメンバを定義する

JavaScriptでは、なにも考えずにメンバを定義すれば、パブリックメンバとなります。 JavaScriptでは、厳密にはプライベートメンバを定義するための構文はありません。 クロージャを利用する事で擬似的にプライベートメンバを定義する事はできます。 （擬似的な、ということの意味は後述します） 


   function Triangle() {
       // プライベートプロパティの定義（底辺／高さを保持）---①
       var _base;
       var _height;
       // プライベートメソッドの定義（引数が正の数値であるかをチェック）
       var _checkArgs = function (val) {
         return (!isNaN(val) && val > 0);
       }

       // プライベートメンバにアクセスするためのメソッドを定義 ----②
       this.setBase = function (base) {
          if (_checkArgs(base)) { _base = base; }
       }

       this.setHeight = function (height) {
          if (_checkArgs(height)) { _height = height; }
       }

       this.getBase = function () { return _base; }
       this.getHeight = function () { return _height; }
   }

   // プライベートメンバにアクセスしない普通のメソッドを定義
   Triangle.prototype.getArea = function () {
       return this.getBase() * this.getHeight() / 2;
   }

   var t = new Triangle();
   t._base = 10;
   t._height = 2;

	// 三角形の面積: NaN // ------③
   document.writeln('三角形の面積: ' + t.getArea() + '≪br />'); 

   t.setBase(10);
   t.setHeight(2);

   document.writeln('三角形の底辺:' + t.getBase() + '<br />'); 
   // 三角形の底辺: 10

   document.writeln('三角形の高さ:' + t.getHeight() + '≪br />');
   // 三角形の高さ: 2

   document.writeln('三角形の面積:' + t.getArea() + '<br />');
   // 三角形の面積: 10

注目していただきたいポイントは２点です。

プライベートメンバはコンストラクタ関数で定義する

プライベートメンバは、以下の構文で、「コンストラクタ関数の中で」定義する必要があります。

構文　プライベートプロパティ／メソッド 


   var プロパティ名
   var メソッド名 = function([引数]){/* メソッドの処理 */}

このように、プライベートメンバを定義する場合には、「this.プロパティ名=～」 「this.メソッド名=～」の thisキーワード ではなく、 var キーワードで 宣言する点に注目です。

_base／ _heightプロパティ、_checkArgsメソッドがプライベートメンバになります。 ③ではプライベートメンバに外部から直接アクセスしようとしていますが、意図したように 値がセットできて「いない」ことが確認できます。

「特権メソッド」を定義してプライベートメンバにアクセスする

プライベートメンバにアクセスできるメソッドのことを 特権メソッド（プリビレッジドメソッド）と言います。 特権メソッドは、「コンストラクタ関数の中で定義する」という点以外は、通常のメソッドと同様の方法 で定義できます。

特権メソッドは、コンストラクタの中で入れ子に定義された関数　-　つまり、クロージャとなっています。 そのため、コンストラクタ関数の中で定義されたプライベートメンバ（要はローカル変数）にも自由に アクセスする事が出来ます。

クロージャの項を思い出していただければわかるように、ここｋではインスタンスに属する特権メソッド （setBase／setHeight／getBase／getHeight）がそれぞれプライベートメンバを参照していますので、 プライベートメンバは、「特権メソッドによって生かされ続けている」とも言えます。

ちなみに、特権メンバには、パブリックメンバやクラス外部から自由にアクセスすることができます。

特権メソッドはJavaScript固有の考え方

JavaやC#のようなオブジェクト指向言語に慣れた方にとって、特権メソッドのような考え方は 耳慣れないものでしょう。JavaやC#などでは、同じクラス内のメンバであれば、プライベートメンバに 自由に自由にアクセスできるからです。

特権メソッドは、クロージャによって擬似的にプライベートメンバを実現しているJavaScript固有の考え方です。 JavaScriptのプライベートメンバには、いわゆる普通の（特権を持たない（prototypeオブジェクトの要素としてのメソッド））パブリックメンバからはアクセスできない点に注意して下さい。

特権メソッドとは、要するにアクセサメソッド。 アクセサメソッドは一般的に「get＜プロパティ名＞」「set＜プロパティ名＞」 の形式で命名します。プロパティ名の頭文字は大文字とします。

そもそもプライベートメンバは使うべきか

ここまで見てきてわかるように、JavaScriptにおけるプライベートメンバの定義方法は一種独特です。 そもそも以下の区分けは、コードを読みにくくする原因ともなるでしょう。

  • プライベートメソッド　⇒　コンストラクタで
  • パブリックメソッド　⇒　プロトタイプオブジェクトで
  • パブリックメソッドでも特権をもつもの　⇒　コンストラクタで

通常のメソッドを特権メソッドにしたい場合に、定義場所を移動させなければならないという問題もあります。 これは些細な事ですが、意外と間違いのもとです。

「それでもプライベートメンバにしたい」局面があるにしても、通常は「すべてパブリックメンバにしてしまう」 ほうがいいと、筆者は思います。 ただパブリックメンバにして終わりではなく、プライベートメンバである事を表すために、プロパティ／ メソッド名の頭にアンダースコアをつけるのです。 少なくとも、これでプライベートメンバである事を識別できます。これで十分なケースも多いはずです。

時と場合によるとは思いますが、開発の生産性／保守性、クラスの安全性などを天秤にかけ、 プライベートメンバ利用の是非を判断してください。

名前空間／パッケージを作成する

クラスの数が多くなってくると、「クラス名がライブラリ同士、あるいは、ライブラリとライブラリを利用している アプリケーションとで競合する」というケースも出てくる。

これは、当然好ましいことではないので、ある程度の規模のクラスライブラリを作成する場合には、 これを名前空間（パッケージ）配下にまとめてしまうことをお勧めします。

たとえば、「Wings名前空間に属するMemberオブジェクト」と「Yamada名前空間に属するMemberオブジェクト」 を別物として区別できるようになります。

JavaやC#のような言語では、このような名前空間（パッケージ）のしくみを標準で備えていますが、 残念ながらJavaScriptにはありません。そこでJavaScriptでは、空のオブジェクトを利用して擬似的に 「名前空間のようなもの」を作成します。 


   var Wings = function () { }//--①

   /* ② */
   Wings.Member = function (firstName, lastName) {
       this.firstName = firstName;
       this.lastName = lastName;
   };

   Wings.Member.prototype = {
       getName: function () {
      return this.lastName + ' ' + this.firstName;
       }
   };
   
   var mem = new Wings.Member('祥寛', '山田');// --③
   document.writeln(mem.getName());// 山田 祥寛

名前空間を定義するには、ただ単に「空のコンストラクタ関数を生成する」だけです。 ①でWings名前空間を定義しています。

あとは、Wings名前空間（オブジェクト）に対して、静的プロパティを追加するのと同じ要領で、 配下に置きたいクラス（コンストラクタ）を定義するだけです（②）。 これによって、Wings名前空間の配下に属するMemberクラスが定義できました。

名前空間配下のクラスをインスタンス化する場合には、名前空間も含んだ名前（完全修飾名）として クラス名を指定する必要があります（③）。

JavaScript のコード内で関数をプロパティとして設定

イベントハンドラの呼び出しのみであるとはいえ、本来、レイアウトを定義すべき HTML の中に JavaScript のコードを混在させるのは好ましくありません。そこで JavaScript では、 関連付けとイベントハンドラそのものの宣言とをまとめて、JavaScript のコード内で記述することもできます。 


    <head>
        <meta charset="utf-8" />
        <title>p205</title>
        <script type="text/javascript">
            <!--
            //ページロード時に実行さえるイベントハンドラを登録
            window.onload = function () {
                /*
		ボタン(btn)クリック時に実行される
		イベントハンドラを登録
		*/
                document.getElementById('btn').onclick = 
		   function () {
                   	window.alert('ボタンがクリックされました。');
                   };
            };
            //-->
        </script>
    </head>
    <body>
        <input id = "btn" type= "button" value="ダイアログの表示" />
    </body>

ここで使用されているのは「匿名関数（関数リテラル）」です。↑ 名前付き関数を使う事も出来ます。↓ 


    <!DOCTYPE html>
    
    <html lang="en" xmlns="http://www.w3.org/1999/xhtml">
    <head>
        <meta charset="utf-8" />
        <title>p205</title>
        <script type="text/javascript">
            <!--
            function btnClick() {
                
                window.alert('ボタンがクリックされました。');
            }
            window.onload =init;
    
            function init() {
                document.getElementById('btn').onclick = btnClick;
            };
            //-->
        </script>
    </head>
    <body>
        <input id = "btn" type= "button" value="ダイアログの表示" />
    </body>
    </html>

しかし、イベントハンドラはその性質上 、複数箇所で使い回す事がほとんどないので、名前付き関数として別に定義するよりも、 匿名関数として直接定義した方が、グローバルな名前空間を汚す事もありません。

この記法を利用する場合は、以下の３点に注意します。

（１）イベント名は全て小文字で記述

window.onLoad ～.onClick のような記述は不可です。

（２）プロパティとして設定するのは関数オブジェクト

プロパティとして設定するのは、あくまで関数オブジェクトであって、関数呼び出しではありません。 たとえば、 onload イベントに init イベントハンドラを関連付ける場合、 


   window.onload = init();

という記述は不可です。正しくは、 


   window.onload = init;

と、記述します。

個別要素のイベントハンドラは onload イベントハンドラ配下に

「document.getElementById.～」の形式でイベントハンドラを登録する場合、 基本的には onload イベントハンドラの配下に記述する必要があります。

getElementById メソッドについては後述しますが、まずは「指定された要素を取得するための メソッド」と思っておけばよいでしょう。対象となる要素が読みこまれる前に、このgetElementById メソッドを呼び出してしまうと、JavaScriptはエラーを返します。onload イベントハンドラの配下 に記述することで、文書全体が呼び出された（読みこまれた後に）getElementById メソッドが実行され ますので、正しく動作します。

イベントハンドラを登録する方法として、addEventListener／attachEvent メソッドを 利用する方法があります。この方法については Chapter 7 で解説します。

ブラウザオブジェクトへアクセスするには

グローバルオブジェクトはアプリケーション課はつ者が意識することのない （また、直接アクセスすることはできない）オブジェクトです。 つまり、クライアントサイド JavaScript では、基本的に Window オブジェクトを意識する必要はありません。 


   //window←先頭は小文字
   window.document.write('こんにちは');

のように記述することはできます。しかし、冗長であるだけで、あまり意味がありません。 この稿ではオブジェクトの従属関係を明示するために window. を省略しない記述を省略しない 記述をします。 window は Windowオブジェクトが自分自身への参照を返す windowプロパティです。

ちなみに、document は、オブジェクトではなくプロパティ名です。 document は、あくまで「Document オブジェクトを参照するプロパティ」です。 しかし、documentプロパティは実体としてオブジェクトを表していることから、便宜上、 document「オブジェクト」と表記することがよくあります。

Window オブジェクトの setInterval は決められた時間感覚で繰り返し 処理を実行します。setTimeout メソッドは、指定された時間が経過したところで一回だけ処理を実行 します。いずれもタイマーを一位に識別するためのID値を返します。このID値は、Window オブジェクト clearInterval メソッドを実行すると無効になります。

    <html lang="en" xmlns="http://www.w3.org/1999/xhtml">
    <head>
        <meta charset="utf-8" />
        <title>p216</title>
        <script type="text/javascript">
            <!--
            // タイマーIDを格納するグローバル変数
            var timer;
            //ページロード時にタイマー処理を登録
            window.onload = function () {
                timer = window.setTimeout(
                    /* 現在の時刻を
                    <div id='result'>タグに表示(3000ミリ秒後の一回)
                    */
                    function () {
                        var dat = new Date();
                        document.getElementById('result').innerHTML = 
                            dat.toLocaleTimeString();
                    },
                    3000
                );
            };
            //-->
        </script>
    </head>
    <body>
      
        <!-- ボタンクリック時にタイマー処理を中止 -->

            onclick="window.clearInterval(timer)" />
        <div id="result"></div>
    </body>
    </html>

ウィンドウサイズやスクロール位置を操作する

Window オブジェクトには、ウィンドウサイズやスクロール位置を操作する為のさまざまな プロパティ／メソッドが用意されています。

ウィンドウを操作するためのプロパティ／メソッド
メンバ概要
moveBy(x, y)ウィンドウ位置を移動（相対座標）
moveTo(x, y)ウィンドウ位置を移動（絶対座標）
resizeBy(x, y)ウィンドウサイズを変更（相対サイズ）
resizeTo(x, y)ウィンドウサイズを変更（絶対サイズ）
scrollBy(x, y)ウィンドウの内容をスクロール（相対位置）
scrollTo(x, y)ウィンドウの内容をスクロール（絶対位置）
blur()ウィンドウからフォーカスをはずす
focus()ウィンドウにフォーカスを当てる（アクティヴにする）
print()ウィンドウの内容を印刷

moveBy／resizeBy はブラウザによっては動作しない。 タブブラウザの場合、複数タブが開いていると動作しない。
