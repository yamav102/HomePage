VBA Friend というスコープと クラスの Instancing プロパティの PublicNotCreatable

Friend というスコープ

VBA の Friend というスコープは、全然特殊な物ではなくて、ごくごく普通に 使われるようになる事が正解なのだと思います。

Public は「本当に外部に公開して良いメソッド、或いは関数なのか」 よくよく考えた末に使う。それだけでは何の役にもたたない下請け関数は、 当然 Private で宣言します。

VBAによるツールを使用するユーザーも「外部」。 Public で宣言したメソッドや関数は Alt+F8 のマクロ画面や、 ユーザー定義関数として、ユーザーは実行できてしまうのだ、と言う 事を考えたら、Public なんておいそれと使えません。

ユーザーに直接利用させる目的で作る、「マクロ」や「関数」という場合も 当然あります。その場合も、本当に使わせたい「マクロ」や「関数」だけがユーザーから 見えるようになっていなければ、使い勝手が悪いです。スコープの宣言に Friend を使うだけで、「外部 」であるユーザーから隠蔽できるのであれば、 こんな良い物を使わないなんて勿体ないでしょう。

とはいえ、Friend は標準モジュールでは使えません。 フォームやシートモジュールに、そのフォームやシートに関係のないメソッドや 関数を押し込んでしまう、というのも、出来てしまうのではありますが、 何が何処に書かれているのか、分類してコーディングしないと混乱するのでやりません。

となると クラスモジュールに書くしかありません。 クラスを使った事が無い人は、「オブジェクト指向とは何か」などと構えなくてよいですから、 標準モジュールだと思って使えば良いと思います。New キーワードでインスタンスを生成してから でないと書いたコードを実行出来ないところが使い勝手の異なるところですが、 FileSystemObject とかがインスタンス生成しないと使えないのと同じなのですから、 使い方は既に知っている事になります。 プロパティは関数。メソッドはプロシージャと原理的に変りません。 プロパティがピンとこないのであれば、モジュールレベル変数を扱う Functionプロシージャを書いておけばよいです。

クラスモジュールに記述した関数やプロシージャは、 Public であっても ユーザーには公開されません。クラスモジュールで Public と Friend を使い分ける意義は、 自プロジェクトの外部にあるプロジェクトを意識しないと出て来ません。

エクセルVBA は自分で書いたコードを DLL として発行する事は出来ないけれど、 自ブックをアドイン化する事はできます。 アドインをアドインとして登録すると、エクセルアプリケーションに対して 常駐する事になりますが、アドインファイルを DLL のように参照設定すると、 参照設定したブック単位で使う事になり、参照設定したプロジェクト内の コードは Public で宣言したオブジェクト、またはプロシージャ、または関数だけが 参照出来るようになります。ここで Friend を使う意義が出てきます。

ある程度の時間「プログラムを書く」という作業に関わっていると、 「自分ってば、またこの処理書いてる。以前造ったデバッグ済みの あのコードがここにあれば」という事が出てきたり出て来なかったり。 そんな時、書き溜めたクラスの塊だけアドインファイルに造っておけば、 開発もサクサクすすむ（筈です）。クラスを沢山造り過ぎると混乱してくるので、 グループ分けしたくなる場合がある（らしい）。 グループ毎にアドインファイルにしておく事も出来るので、 これはパッケージと同じ機能の実現なんではないか。 （間違いを書いていたら叱って欲しい）。

開発がサクサク進むとしても、引き渡す際にアドインファイルも 一緒に渡さなくてはならなくなる、という問題は残ります。 使用している DLL が無ければ動作しないというのは、数多あるアプリケーションと 条件は変わらない筈なのですが、ちょっと照れてしまい自分には出来ません。 しかし、十数個のアドインを参照設定して利用されているエクセルというものを、私は 見た事があります。どの程度一般的に行われているのかは知らないけれど。

自分なら、使ったクラスは、自ブックのクラスとしてコピペなりして、 改めて動作テストする事にすると思うが、それでもメリットの方が大きいと思うのです。

クラスの Instancing プロパティの PublicNotCreatable

外部プロジェクトでクラスを利用するには、クラスの Instancing プロパティを PublicNotCreatable に しておかないと参照出来ません。そして、NotCreatable とあるように外部からインスタンスの生成が出来ない、ので、 インスタンスを Get する為の関数を用意しておく必要があります。 この関数はアドインファイルの ThisWorkbook モジュールに 書いておけばユーザーから隠す事が出来ます。 に modPublicObjcts モジュールとかいう 名前の標準モジュールを用意して書いておけばいいんじゃないか。 標準モジュールに Public で書いても、ファイル自体がアドインなので ユーザーからは隠蔽されているのです。以下に手順を書いてみます。

アドインにするファイルに Class1 モジュールを用意します。 


Option Explicit
'外部プロジェクトで利用するクラス：Class1モジュール

'プロジェクト外にも公開するメソッド
Public Sub classPMethod()
    MsgBox "classPMethod"
End Sub

'プロジェクト外には非公開だが、自プロジェクト内には公開するメソッド
Friend Sub classFMethod()
    MsgBox "classFMethod"
End Sub

'コンストラクタ
Private Sub Class_Initialize()
    MsgBox "Initialize"
End Sub

'デストラクタ
Private Sub Class_Terminate()
    MsgBox "Terminate"
End Sub

Instancing プロパティは PublicNotCreatable に設定します。


アドインにするファイルの ThisWorkbook モジュール に、 Class1 のインスタンスを返す関数を Public で用意します。 


Option Explicit
'プロジェクト外部に公開するオブジェクト達
'ThisWorkbookモジュール

Public Function obj1() As class1
    Set obj1 = New class1
End Function

プロジェクトに名前を付ける。 DLL の定義がどうなっているのかは調べていないが、Dynamic で Link な Library ではあるだろう。

ファイルをアドインとして保存して閉じる。

アドインファイルを利用する新規ブック（新規プロジェクト） を作成し、アドインファイルを参照設定する。
