■Win32APIメモ-関数の書き方/使い方-

APIの宣言の組み立て

●関数名の指定↓

関数名は、基本的にC言語で宣言されたAPIの関数名と同じものを使います。 関数の引数・定数・構造体の意味に関しては MSDNライブラリ(英語版)で 検索すると詳細情報に辿り着けます。(2009.6現在) 

Declare Function GetWindowsDirectory　...

関数名を自作しても（Alias節が正しければ）動作するが、慣習としてMicrosoftが定めた関数名を使用する。

値を返さないAPI関数を宣言するときは、Function ではなく Sub を使用する。

●ライブラリの指定↓

APIのWindowsライブラリ Kernel32.dll, User32.dll, Gdi32.dll の３つに限っては、「Lib "Kernel32"」と拡張子を省略できる。その他のAPI関数を呼び出すときは「Lib "advapi32.dll」のように拡張子を記述する。 

Declare Function GetWindowsDirectory Lib "kernel32"　...

●DLLで公開されている正式な関数名の指定↓ 

Delcare Function GetWindowsDirectory Lib "kernel32" _
    Alias "GetWindowsDirectoryA" _　...

GetWindowDictoryという関数は実際には存在せず、「GebWindowsDirectoryA」 と「GetWindowDirectoryW」の２つの関数名がDLLの中で公開されている。 上記の書き方は、Alias節で、このうち「GetWindowsDirectoryA」を指定している。

Alias節で使われる関数名は大文字と小文字を区別する。 Alias "GETWINDOWSDIRECTORYA"と書くとエラーになる。

●引数の指定と、戻り値データ型の指定（完成） 

Declare Function GetWIndowsDirector Lib "kernel32" _
   Alias "GetWindowsDirectoryA" _
   (Byval lpBuffer As String, _
   Byval nSize As Long) As Long

API関数は32ビットの値を返し、VBAでは一般的にLong型になる。

宣言はモジュールの先頭に記述し、既定でPublicになる。 標準モジュール以外で宣言した場合、Publicで宣言しても、 Privateと見なされる。

●完成したコードとAPI関数の利用例 


Declare Function GetWindowsDirectory Lib "kernel32" _
    Alias "GetWindowsDirectoryA" _
    (ByVal lpBUffer As String, _
    ByVal nSize As Long) As Long

    
'API　GetWindowsDirectoryAはANSI用。
'GetWindowsDirectoryWはUnicode用なので、
'Unicodeで動作するVBAではGetWindowsDirectoryWを
'使うようにも思えるが、VBAがAPIに引数を渡すとき
'自動でANSIに変換してしまう。そのため
'GetWindowsDirectoryWを使うことはできず、
'常にGetWindowsDirectoryAを使用することになる。


Public Const MAX_PATH = 260 'パスの最大長

'260はC言語で定義されている。
'APIはC言語で書かれている。
'VBAからAPIに文字列を渡すにはNULL(文字コード:0)で
'埋めて渡す必要がある。


'summary:Windowsディレクトリのパス名
Sub GetWindowsDirectory_Sample()

    Dim strBuffer As String * MAX_PATH
    Dim rc As Long 'rc:リターンコード
    
    Dim strPrompt As String
    
    'Windowsディレクトリのパス名を取得
    rc = GetWindowsDirectory(strBuffer, Len(strBuffer))
    
    'rcには関数の返り値のANSIでの文字列長が代入される。
    'API関数の返り値はディレクトリのパス名ではなく
    'パス名の文字列長を返すだけ。API関数実行時に、
    '260のNULL文字が、
    'Windowsディレクトリのパス＋260に満たない分の
    'NULL文字に置き換えられるので、
    'VBAでは置き換えられた後のAPI関数の引数からNULL文字を
    '取り除いた値用いる。

    '取得したデータから必要な文字列だけ抽出
    strPrompt = Left(strBuffer, InStr(strBuffer, vbNullChar) - 1)
	
    'strPrompt = Left(strBuffer, rc)
    '↑こう書いても正常に動作するが、
    'rcはANSIでの文字列長なのでAPIが２バイト文字の引数を
    '返した場合（妙な表現たが）文字列長が倍になってしまい
    '（実際には２バイト文字を返すことは無いのだが)、余計な
    'NULL文字を含む値を取得してしまうことになり、
    '厳密には間違った書き方となる。
    	
    MsgBox "Windowsディレクトリのパス名： " & strPrompt
End Sub

NULLで埋めるということ

Public Const MAX_PATH = 260 'パスの最大長
   Dim strBuffer As String * MAX_PATH

上記のコードは、固定長文字列で宣言する書き方。 固定長で宣言すると、自動的にデータはNULLで埋まる。 

Public Const MAX_PATH = 260 'パスの最大長

    Dim strBuffer As String
    strBuffer = String(MAX_PATH, vbNull)
    'strBuffer = String(MAX_PATH, 0)とも書ける

のように、可変長で宣言した場合は、String関数を使って、 引数をNULLで埋める。

API関数に文字列引数を渡すという事

VBAの場合、ByValキーワードで関数に「値渡し」した引数は、影響を受けない。 VBAユーザーには、上に揚げたAPIサンプルの挙動が 奇っ怪で飲み込み難い。 ただし、ByRefキーワードを使用するか省略した場合は引数は 「参照渡し」となり変化する。これがVBA環境での常識。 

Sub AtaiWatashi()
   Dim i As Long
   Dim rc As Long
		
   i = 1
   rc = FunctionA(i)
        
   MsgBox "rc = " & rc & " ; " & "i = " & i 
'ここで関数に渡した引数が変化する事など無い
End Sub

Function FunctionA(ByVal l As Long) As Long
	
    l = 2
    FunctionA = l
    
End Function

結論として、C言語に文字列の引数はByValキーワードを 使う事によってのみ値を渡せる仕組みになっている。 (32ビットのメモリアドレス{ポインタと呼ばれる}を渡している) そして、渡してしまった 引数は預け先の関数の影響を受ける事になる。 異なる言語で変数をやりとりする 以上VBA環境での常識が通らないという事を受け入れる事が重要。 (数値を引数として渡す場合はByVal/ByRefの仕様はVBA環境のまま使用できる。)

Longで宣言するという事

C言語で書かれたWIN32API関数は符号なし32ビット長整数を 扱うことができる（unsingned long型）。しかし、VBAには 対応する型のサポートが無いため、（しかたなく）符号付き32ビット 長整数型のLongで代用する事になる。しかたなく使っている以上 ここには落とし穴がある。

unsigned long と long範囲の比較
言語データ型値の範囲
C言語符号なし長整数0～4,294,967,295
VB符号付き長整数-2,147,483,648～2,147,483,647

落とし穴とは、APIがLongの上限を超えた値を返す時、オーバーフローにはならず、 Longの最上位ビットに1が立ち、負数を返してくる事である。 なので、Longに負数が返った場合には、返ってきた負数に2^32を加算し、「正」の 値に反転させて使わなければならない。8ビットで考えると、
1,1,1,1,1,1,1,1 は、[符号なし]では255をあらわすが、[符号付き」では、 最上位ビットが負数を表し、負数の最大値である-1を表す。-1が返ってきたら、 2^8を加算してやれば、[符号なし]の値である255を取得する事ができる。

その他引数を渡す時の概要

●引数が構造体の時

VBAではユーザー定義型を作成して、APIの構造体に値を渡します。 VBAのユーザー定義型は参照渡し(ByRef)でのみ値を渡せるように設計されているので、 ByValキーワードを使用する事はできません。
例）：CreateProcess関数

●引数が配列の時

Win32APIは基本的に、VBAから配列全体を引き受ける事はできない。 For...Nextステートメントのようなループで順番に渡す事になる。 しかし、数値配列に限り配列全体を渡すことができる。

●引数がNULLの時

引数が文字列の場合は[vbNullString]を使い、 引数が長整数の場合は[0&]を使用する。
例）：FindWindow関数

●As Any節

Win32APIには、１つの引数で複数のデータ型を受け取れるものがある。 引数を「As Any」と宣言すると型の制限をなくします。 「As Any」を使用すると参照渡しになる。
例）：CreateProcess関数

引数 arglist 内では、標準のデータ型以外に As Any も指定できます。 Any を指定すると、データ型のチェックを抑止し、任意のデータ型をプロシージャに渡せます。

●Win32APIの「True」とVBAの「True」

VBAのTrueは[-1]ですが、C言語のTrueは[1]であり、APIが Trueを返した場合、Trueの判定には注意を要する。 （Falseはともに[0]であり同じように比較できる。) 

If (戻り値) = True Then

と書くと、-1 と 1 を比較するという無意味な作業になり間違いを犯す。

If (戻り値) <> False then

と書くと、正しく判定することができる。 VBAのIF文は、Trueだから評価されるのではなく、Falseで無い場合に評価されるので、 以下のようにも書ける。 

'if 1 then msgbox "[1]でも[-1]でも実行される"
'if -1 then msgbox "[1]でも[-1]でも実行される"
If (戻り値)  then
